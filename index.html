Designing an AI-Native SRE Platform

BACCA.AI is an AI engineer for on-call teams. It picks up a production alert, investigates it against live telemetry the way a senior SRE would, and returns a root cause with its reasoning attached.

The brief

A Slack plugin, not a product.

The agent worked; everything it knew arrived as a message in a thread. There were no objects, no navigation, no states. Our job was the form: decide what this thing is as software, and leave the client's engineers a system they can extend without us.

What we were handed. The request scrolls away in the channel; the root cause comes back as a thread you read once.

01 — Product definition

Deciding what the product is made of

I took the plugin apart: every message it sent, every thing it knew but never showed. Each one got a name and a place. This map was the first thing we delivered, and every screen after it is downstream of these calls.

02 — Representation

Reasoning as a graph, not a paragraph

Engineering already produced the reasoning as a tree. What it should look like was undecided, and that part was ours. A paragraph gets read once and cannot be interrogated, so the same data became a canvas: the firing alert, the context gathered against it, the hypotheses branched from that, the queries run to test each one. Status sits on the node itself, so a skim tells you where the agent was certain and where it guessed.

Alert → context → hypotheses → actions → conclusion. Refuted branches are dimmed, never deleted.

03 — Configuration

Settings had to become a place

In the Slack plugin, Bacca’s capabilities were already configurable through App Home. What changed was not the feature set — it was what configuration had become: more capabilities, more integrations, and a second admin who needed to know how the first one had set it.

04 — System

A language the team keeps speaking

Six areas and three detail surfaces, one designer. Nothing scales unless the decisions live outside the file, so colour, type and elevation were documented as variables and every screen inherits them, including the ones the client builds after us.

05 — Delivery

The handoff changed shape mid-project

An agent product changes weekly, and a vendor who answers in sprints stops being useful. So how fast a decision reaches something the client can click became part of what we were selling. Same design system, three different ways of handing it over.
